# 代码审查清单

本项目代码审查按以下清单逐项执行，重点覆盖安全性、前后端契约、代码质量与工程规范。

## 1. 安全审查

- [ ] 配置文件中无明文密钥（数据库密码、API Key、MinIO 密钥等应通过环境变量注入）
- [ ] 所有按 ID 操作的接口均校验资源归属（防止越权访问/操作他人数据）
- [ ] 用户资料更新仅允许白名单字段，禁止直接接收实体类做批量赋值
- [ ] 接口响应不返回密码哈希等敏感字段
- [ ] 异常信息不向客户端泄露内部细节（数据库错误、堆栈等）
- [ ] 参数校验使用 `@Valid` + DTO 注解，校验失败返回明确提示
- [ ] JWT 密钥强度足够，登录态有过期与失效处理
- [ ] 上传文件有类型/大小限制，删除数据时同步清理存储对象
- [ ] CORS 仅放开可信来源

## 2. 前后端契约审查

- [ ] 前端请求字段与后端 DTO 字段一致（大小写、命名）
- [ ] 后端响应字段与前端读取字段一致
- [ ] 枚举/状态值（合同状态、风险等级、房源状态）前后端取值一致
- [ ] 日期、金额、布尔字段的格式与类型一致
- [ ] 错误码与 HTTP 状态码的约定前后端一致，token 失效能正确跳转登录

## 3. 代码质量审查

- [ ] 服务层不重复解析 token，统一从安全上下文取当前用户
- [ ] 涉及多步写入的方法使用事务（`@Transactional`）
- [ ] 无未使用的类、方法、依赖（死代码需清理）
- [ ] 日志不输出敏感信息（SQL 日志、密钥等）
- [ ] 命名清晰、注释使用中文且不过度

## 4. 依赖与版本

- [ ] 使用的框架版本处于官方支持周期内
- [ ] 第三方 API 的模型名/接口与官方最新文档一致
- [ ] 新依赖变更前先联网确认最新稳定版本

## 5. 工程规范

- [ ] `npm run build` 通过
- [ ] `npm test` 通过（若无测试框架，需说明）
- [ ] `mvn compile`（或 `mvn test`）通过
- [ ] 修改范围仅限任务相关文件
- [ ] 不向版本库提交密钥、构建产物、临时脚本

## 6. 提交前检查

- [ ] 按以上清单逐项核对
- [ ] 运行完整检查命令并保存输出作为证据
- [ ] 确认工作区无无关改动
